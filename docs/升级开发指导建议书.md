| 文档版本 | 1.0 |

| 配套文档 | [程序基本架构说明书.md](./程序基本架构说明书.md) |

本文给出可落地的演进路线与二次开发上手指引。默认策略：**先工程卫生与模块化，再 Direct3D 渲染与流式 I/O，最后 IPC / 暗色 / 安装器**——与作者 TODO 及近年性能修复方向一致。

---

## 1. 现状评估与技术债

### 1.1 现状摘要

voidImageViewer 已在 Win32 + GDI+/GDI + libwebp 路径上形成完整可用产品：打开快、动画可用、播放列表与 Everything 集成成熟。1.0.0.9 起引入 WebP、mipmap、preload；1.0.0.11 起 cache_last；近期版本持续修复大图滚动、预加载一致性、GDI 泄漏与防休眠等问题。

核心矛盾是：**功能密度集中在单文件 `viv.c`（约 15000 行）**，渲染抽象与现代 UI（暗色、高 DPI）尚未落地，加载模型仍偏「整文件进内存」。

### 1.2 技术债清单

| ID | 债务 | 影响 | 证据位置 |
|----|------|------|----------|
| D1 | 巨型单体 `viv.c` | 难测、难并行开发、合并冲突高 | `src/viv.c` |
| D2 | 未启用渲染后端大体积死代码 | 干扰阅读与编译感知；抽象未闭环 | `render_d3d.c`、`render_opengl.c`（`#if 0`）、`render.h` |
| D3 | 整文件 `CreateStreamOnHGlobal` | 大图内存峰值高；不利于管道/STDIN | `_viv_load_image_thread_proc` |
| D4 | 加载线程状态机复杂 | 预加载/中断/多帧历史 bug 多 | `Changes.txt` 1.0.0.11–0.13 |
| D5 | 构建配置变体多 | ALPHA/BETA/LITE 等增加认知负担 | `vs2019/voidImageViewer.vcxproj` |
| D6 | 暗色 / 高 DPI / 本地化未做 | 现代 Windows 体验缺口；暗色需自绘控件 | `viv.c` TODO |
| D7 | 安装器缺口 | MSI、仅当前用户、ARM 安装包未完成 | `viv.c` TODO、`nsis/` |
| D8 | 开发者文档原缺失 | 上手依赖读源码 | 已由本 `docs/` 补齐基线 |

## 2. 演进原则

1. **保持产品基因**：轻量、启动快、Win32 原生、优先「尽快显示第一帧」。
2. **小步可回滚**：每一阶段以「行为不变」的搬迁或开关隔离为先，再换实现。
3. **兼容优先**：不破坏现有 `voidImageViewer.ini` 键名与常用命令行；新能力用新键 / 新开关。
4. **先边界后功能**：模块边界清晰后再上 D3D、IPC、STDIN 管道。
5. **回归对照历史缺陷**：改加载 / 渲染 / 导航时，强制跑第 5 节清单。
6. **不重写整个栈**：避免全量 C++ 化或立刻废弃 GDI；GDI 应长期作为回退。

## 3. 分阶段路线图

```mermaid

  P0[P0 工程卫生]
  P1[P1 模块化拆分]
  P2[P2 渲染后端]
  P3[P3 格式与IO]
  P4[P4 体验与平台]

  P0 --> P1 --> P2
  P1 --> P3
  P2 --> P4
```

### 3.1 P0 — 工程卫生（优先，低风险）

**目标**：降低噪声，为拆分做准备，不改变用户行为。

| 任务 | 建议做法 |
|------|----------|
| 隔离死代码 | 将 `render_d3d.c` / `render_opengl.c` 移出默认编译（排除项或独立 `#ifdef VIV_ENABLE_LEGACY_RENDER`）；或移至 `src/legacy/` 并不链接 |
| 标注模块边界 | 在 `viv.c` 用一致分区注释：`// --- load ---`、`// --- paint ---`、`// --- playlist ---` 等，为物理拆分做地图 |
| 文档化构建 | 在 README 或本 docs 中标明推荐配置：`vs2019` + Release \| x64 |
| 清理噪音 | 约定 Debug 才启用冗长 `debug_printf`；避免 TODO 与生产逻辑混读困难（可迁到 `docs/TODO-backlog.md`，可选） |
| 基线构建验证 | Win32 / x64 各打一包，确认排除死代码后无链接缺失 |

**完成标准**：默认工程更干净；Release 行为与 1.0.0.15 一致。

### 3.2 P1 — 模块化拆分（行为不变）

**目标**：把 `viv.c` 按职责物理拆分，**先搬迁、不改算法**。

建议拆出的编译单元（命名可微调）：

| 新单元 | 迁出内容 | 关键现有符号 |
|--------|----------|--------------|
| `viv_load.c` | 加载线程、回复队列 | `_viv_load_image_thread_proc`、`_viv_reply_*`、`_VIV_WM_REPLY` |
| `viv_paint.c` | `WM_PAINT`、mipmap、缩放尺寸计算 | `_viv_get_mipmap`、`_viv_get_render_size` |
| `viv_playlist.c` | 播放列表、shuffle、排序比较 | `_viv_playlist_*`、`_viv_fd_compare`、`_viv_next` |
| `viv_options.c` | 选项对话框与树控件 | `_viv_options*` |
| `viv_cmdline.c` | 命令行解析与帮助文本 | `_viv_process_command_line`、`_viv_command_line_options` |
| `viv.c`（瘦身后） | 窗口过程、命令分发、生命周期 | `_viv_proc`、`_viv_command`、`_viv_init` / `_viv_kill` |

**实施注意**：

- 大量 `static` 全局需提升为「模块内 extern」或集中到 `viv_state.h` 式状态头——优先最小暴露。
- 每拆一个文件：全量手动回归打开 / 动画 / 下一张 / 全屏 / 选项保存。
- 暂不引入新框架或 C++。

**完成标准**：`viv.c` 显著瘦身；功能与 INI 兼容；x64 Release 通过常规使用路径。

### 3.3 P2 — 渲染后端（Direct3D 优先，GDI 回退）

**目标**：落地已有 [`src/render.h`](../src/render.h) 的 `render_t` 抽象；缩小缩放场景优先走 D3D（与 TODO「Use Direct3D to render images when shrinking」一致）。

| 步骤 | 说明 |
|------|------|
| 1 | 修正并补全 `render_t`（当前头文件函数指针声明存在语法不完整风险，接入前需整理） |
| 2 | 实现 `render_gdi` 适配层：包装现有 `WM_PAINT` 逻辑，保证行为基线 |
| 3 | 实现 `render_d3d`：纹理上传、窗口尺寸变化、缩小过滤；大图局部放大可按 TODO 先裁剪再 stretch |
| 4 | 运行时选择：INI 键如 `renderer=gdi|d3d`（默认 gdi，稳定后再默认 d3d） |
| 5 | OpenGL 列为更后选项；勿在抽象未稳时并行两套新后端 |

**完成标准**：GDI 与 D3D 可切换；缩小性能或驱动兼容问题可隔离；无 mipmap/GDI 对象泄漏回归。

### 3.4 P3 — 格式与 I/O

**目标**：降低大文件峰值，打通管道与剪贴板工作流（作者与社区 TODO 集中区）。

| 优先级 | 能力 | 备注 |
|--------|------|------|
| 高 | 流式 / 分块加载评估 | 在不影响 GIF 首帧时序前提下，减少 HGlobal 整包；可按格式分流 |
| 高 | `clipboard:` / `stdin:` 伪路径 | TODO 已点名；配合 CF_DIB / 管道 |
| 中 | 文件变更自动刷新 | 目录监视或手动 Refresh 增强 |
| 中 | APNG | 新格式；评估 GDI+ 能力或第三方解码 |
| 中 | 外部滤镜管道 | 调用 ImageMagick/GraphicsMagick：显示图 → STDOUT → STDIN 回显，不落盘 |

**完成标准**：至少一种非文件源（剪贴板或 STDIN）可显示；大图内存峰值有可测改善或文档化限制。

### 3.5 P4 — 体验与平台

| 项 | 建议策略 |
|----|----------|
| 暗色模式 | Win32 无完整系统暗色控件；需自绘客户区与部分控件，或分阶段只做客户区背景/菜单自绘 |
| 高 DPI | 清单已有 Manifest 基础；补高 DPI 图标与工具栏图像条 |
| 本地化 | 资源 string table；先中英分离字符串，避免硬编码英文散落 |
| 标题栏格式 UI | `config_title_bar_format` 已有 INI，补选项页控件（TODO 首条） |
| 安装 | MSI 或增强 NSIS：当前用户 `%LocalAppData%\Programs`、ARM/ARM64 安装包 |
| MinGW | 单独分支验证；不阻塞 MSVC 主线 |

### 3.6 P5 — 集成能力

| 能力 | 说明 |
|------|------|
| IPC get/set | 图像宽高、显示区尺寸、缩放、当前文件名（剪贴板/STDIN 时保留「上一文件」语义） |
| 多实例协同 | tile/cascade、「Play All Instances」；需实例发现机制 |
| 播放列表文件 | m3u / efu / 纯文本文件列表；命令行加载 |
| 子文件夹浏览 | next/prev 可选递归 |
| 与 Everything | 随机化快捷键、shuffle 索引列表优化等小项 |

**完成标准**：对外 IPC 有稳定消息协议文档；播放列表文件可回归测试。

## 4. 二次开发上手指南

### 4.1 环境与构建

1. 安装 Visual Studio 2019（或兼容的 MSBuild + v142 工具集）与 Windows 10 SDK。
2. 打开 [`vs2019/voidImageViewer.sln`](../vs2019/voidImageViewer.sln)。
3. 推荐配置：`Release` + `x64`（亦可验证 Win32）。
4. 输出产物与 NSIS 脚本路径以工程设置为准；本地调试可直接运行生成的 `voidImageViewer.exe`。

无需单独构建整个 `libwebp/` 顶层工程；vcxproj 已编入所需源文件。

### 4.2 关键符号入口表

| 意图 | 从这里读起 |
|------|------------|
| 启动 / 退出 | `crt.c` → `WinMain` → `_viv_main` → `_viv_init` / `_viv_kill` |
| 菜单与快捷键命令 | `_viv_command`、`viv.h` 中命令 ID |
| 打开文件 | `_viv_open_from_filename` → `_viv_open` → `_viv_load_image_thread_proc` |
| 绘制 | `_viv_proc` 内 `WM_PAINT`；`_viv_get_mipmap` |
| 下一张 | `_viv_next` |
| 设置读写 | `config_load_settings` / `config_save_settings`；变量在 `config.h` |
| WebP | `webp_load`（`webp.c`） |
| Everything | `_viv_search_everything`；协议见 `everything_ipc.h` |
| 版本号 bump | `src/version.h` + `Changes.txt` 记一笔 |

### 4.3 常见改动面

| 改动类型 | 主要触点 |
|----------|----------|
| 新增配置项 | `config.h` 声明 → `config.c` 默认值 / load / save → 选项对话框（`viv.c` 或未来 `viv_options.c`）→ `res` 控件 |
| 新增菜单命令 | `viv.h` ID → 命令表 → `_viv_command` 分支 → `voidImageViewer.rc` 菜单 |
| 快捷键 | 默认键表 + `viv_key_add` 持久化路径；Controls 选项页 |
| 新图像格式 | `_viv_load_image_thread_proc` 解码分支；文件过滤器字符串；关联安装表 |
| 渲染行为 | 当前改 `WM_PAINT`；P2 后改对应 `render_*` |

### 4.4 调试建议

- 使用 `debug_printf`（`debug.c`）；确认工程 Debug 宏与输出终端/调试器配置。
- Debug 分配器（`mem.c`）可用于抓泄漏；对照历史上 mipmap/refresh 的 GDI 泄漏修复。
- 多线程问题：在 UI 回复处理与 `_viv_load_image_terminate` 路径打断点，避免只在加载线程看现象。
- 单实例调试：可临时开 `config_multiple_instances` 或关掉已运行实例，避免 `WM_COPYDATA` 转发到旧进程。

### 4.5 建议的本地回归最小集

每次改加载 / 渲染 / 导航后至少验证：

1. 打开大 JPEG / 动画 GIF / 动画 WebP。
2. 快速连续下一张（含 preload 开启时）。
3. 加载中途再切换文件（中断多帧）。
4. 全屏 ↔ 窗口、缩放、滚动大图。
5. 幻灯片下屏保/休眠是否仍被抑制。
6. 退出后 INI 几何与排序是否保留。

## 6. 建议不做或谨慎做的事

| 不建议 | 原因 |
|--------|------|
| 全量 C++/Qt/WPF 重写 | 丧失轻量优势；迁移成本远高于模块化 |
| 立即删除 GDI 路径 | 兼容与回退需要；应开关共存 |
| 抽象未稳时并行上 OpenGL + D3D | 双后端维护成本高；先 D3D（与 TODO 一致） |
| 无协议文档的随意 IPC | 易与单实例 `WM_COPYDATA`、Everything 消息冲突 |
| 破坏性改 INI 键名 | 用户配置丢失；需迁移器或双读 |
| 在 `viv.c` 继续堆千行新功能 | 先 P1 拆分再加功能，否则债滚雪球 |
| 为「现代化」引入重运行时 | 与 voidtools 工具风格不符 |

## 9. 交付与版本管理建议

1. 功能变更同步更新 `Changes.txt`（项目既有风格：日期 + 版本 + 条目列表）。
2. 修改用户可见行为时 bump [`src/version.h`](../src/version.h) 的 `VERSION_BUILD`。
3. 架构级变更（新渲染器、INI 新节）同步改 [程序基本架构说明书.md](./程序基本架构说明书.md)。
4. 对外 IPC / 播放列表格式一旦稳定，单独增加 `docs/协议与格式.md`（需要时再写，避免过早文档债）。

---

## 10. 结语

voidImageViewer 的升级价值在于：**保持「快而准」的查看器内核**，同时通过模块化与可选 D3D/流式 I/O 化解单体与内存模型瓶颈，再谨慎扩展 IPC 与现代 UI。按 P0→P5 推进，可在不牺牲现有用户配置与使用习惯的前提下，可持续接纳 TODO 与社区需求。
